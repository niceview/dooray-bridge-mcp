# dooray-bridge

두레이(Dooray) 업무와 댓글을 Claude Desktop에서 읽고, 정해진 쓰기 여섯 가지를 허락을 받아 하게 해 주는 확장입니다.
두레이 공식 API만 쓰고, 내 컴퓨터에서 내 토큰으로만 돕니다.

- "sample 프로젝트에서 이번 주에 바뀐 것 요약해 줘"
- "내가 담당인데 2주 넘게 멈춘 업무 찾아 줘"
- "나 멘션한 댓글 있어?"
- "방금 올린 댓글에서 '내일'을 '모레'로 고쳐 줘"

이 문서는 설치하고 쓰는 방법입니다. **이 프로그램을 믿어도 되는지 판단할 자료는 [`SECURITY.md`](SECURITY.md)에 있습니다 — 설치 전에 읽어 주세요.** 개발하는 사람을 위한 문서는 [`docs/development.md`](docs/development.md)입니다.

## 1. 준비물

- Mac(macOS) 또는 Windows PC — Mac에서 시험했고, Windows는 0.3.4부터 설치할 수 있습니다(설치 한 대 확인).
- Claude Desktop — 2.9939.2에서 시험했습니다. 그보다 오래된 버전이면 먼저 업데이트하세요.
- 두레이 계정
- 인터넷 연결 — 설치할 때 실행에 필요한 것들을 내려받습니다.

Claude 요금제가 Team·Enterprise라면 조직 소유자가 확장을 허용해야 할 수 있습니다.

## 2. 설치

### 토큰 발급

1. 두레이에서 **개인설정 > API > 개인 인증 토큰**으로 갑니다.
2. 토큰을 새로 발급하고 화면의 값을 복사합니다. 바로 다음 단계의 토큰 칸에 붙여 넣습니다.

토큰은 **내 두레이 계정과 같은 권한**을 가집니다. 읽기만 하는 토큰은 두레이에 없습니다.
메신저·메일·문서에 붙여 넣지 마세요. 누구에게도 보내지 않습니다.

### 확장 설치

1. [Releases 페이지](https://github.com/niceview/dooray-bridge-mcp/releases/latest)에서 `dooray-bridge-버전.mcpb` 파일을 내려받습니다.
2. 받은 파일을 **더블클릭**합니다. Claude Desktop의 설치 화면이 열립니다. (열리지 않으면 Claude Desktop **설정 > 확장 프로그램 > 고급 설정 > "확장 설치…"** 에서 그 파일을 고릅니다.)
3. 설치 화면에 제작사가 `niceview`로 보이고 **붉은 경고문**이 보입니다. 이 확장이 컴퓨터의 모든 항목에 접근할 수 있고 개발자 정보를 Anthropic이 확인하지 않았다는 내용입니다. Anthropic의 목록에 올리지 않고 직접 배포하는 확장에는 늘 나오는 문구입니다. 실제로 하는 일과 하지 않는 일은 `SECURITY.md`에 있습니다.
4. 설정 칸 두 개를 채웁니다.
   - **두레이 개인 인증 토큰**: 방금 복사한 값. 입력한 글자는 가려집니다.
   - **두레이 웹 주소**: 브라우저로 두레이를 열었을 때 주소창의 앞부분. `https://`부터 넣습니다. 예: `https://회사이름.dooray.com`
   - **토큰을 웹 주소 칸에 붙이지 마세요.** 웹 주소 칸의 값은 가려지지 않고 설정 파일에 그대로 남습니다.

설치할 때 Claude Desktop이 실행 프로그램 `uv`를(이 컴퓨터에 없을 때만), `uv`가 Python과 필요한 부품을 내려받습니다. 시간이 걸릴 수 있습니다. 무엇을 어디서 받는지는 `SECURITY.md` 4절에 있습니다.

### 확인

새 대화를 열고 이렇게 씁니다: **"두레이 whoami 불러 줘"**

내 이름, 접근 가능한 프로젝트 수, `쓰기 도구: 등록됨`으로 시작하는 줄이 나오면 통과입니다. 오류 문장이 나오면 6절을 봅니다.

## 3. 쓰기와 허락

두레이에 쓰는 일은 여섯 가지뿐입니다: 업무에 댓글 등록, 내 개인 프로젝트나 지정한 프로젝트에 업무 만들기, 상위 업무 지정·해제, 이미 있는 업무·댓글 고치기(제목·본문·담당·참조·마감·태그·마일스톤·우선순위·상태, 댓글 본문), 업무를 다른 프로젝트로 옮기기(내가 멤버인 프로젝트 사이에서만), 프로젝트 설명 고치기(내가 어드민인 프로젝트만). 지우기·파일 올리기는 없습니다.

순서는 언제나 같습니다.
1. Claude가 무엇을 어디에 쓸지 보여 줍니다. 고치기면 바뀌기 전과 후를 보여 줍니다.
2. 내가 읽고 "올려 줘"·"고쳐 줘"라고 말합니다.
3. **허락 창**이 뜹니다. 도구 이름과 넣을 값(업무 번호, 내용)이 보입니다. 대화에서 내가 허락한 그 일이 맞는지 확인하고 **"한 번만 허용"** 을 누릅니다. "거부"를 누르면 두레이에 아무것도 가지 않습니다.

꼭 알아 둘 것:
- **"항상 허용"을 누르지 마세요.** 누르면 그 도구는 그 뒤로 창 없이 실행됩니다. 매번 읽고 허락하는 것이 이 확장의 안전장치입니다. 실수로 눌렀다면 **설정 > 확장 프로그램 > Dooray Bridge > 구성**의 도구 권한에서 "승인 필요"로 되돌립니다.
- 댓글에 `@홍길동` 처럼 사람을 부르면(멘션) 그 사람이 업무의 참조에 추가되고 알림을 받습니다. 담당·참조에 사람을 넣어도 알림이 갑니다. **되돌릴 수 없습니다.**
- 올린 댓글·만든 업무는 이 프로그램으로 지울 수 없고, 고친 글의 이전 내용도 되찾지 못합니다. 두레이 화면에서 직접 처리합니다.
- 글에 이미 있는 링크를 고치는 길로, 그 업무에 없는 사람에게 알림이 가는 고치기가 만들어질 수 있습니다. 고치기를 두 번 이상 이으면, 링크가 없던 글에서도 아무 사람이나 그룹을 부르는 멘션을 만들 수 있습니다. 이 프로그램은 이것을 막지 않습니다 — 막는 것은 대화에서의 승인과 허락 창입니다. 허락 창에서 old나 new에 dooray://, members, 긴 숫자가 보이면 누르기 전에 확인하세요.
- **두레이 일은 채팅에서 하세요.** Code 탭에서는 설정에 따라 쓰기 도구가 허락 창 없이 실행될 수 있습니다.
- 답변 말투를 저장할 때(`set_reply_style`)도 허락 창이 뜹니다. 이것은 이 컴퓨터의 설정 파일에만 쓰고 두레이로는 보내지 않습니다.
- 업무를 다른 프로젝트로 옮기면 업무 번호가 바뀝니다. 다시 옮겨 와도 옛 번호로 돌아오지 않고, 하위 업무가 함께 가고, 두레이 문서에 따르면 태그와 단계 정보가 사라집니다. 원래 프로젝트의 목록에서는 빠집니다. 팀 프로젝트의 업무를 내 개인 프로젝트로는 내가 만든 업무만 옮깁니다.
- 프로젝트 설명을 고치면 그 프로젝트의 멤버 모두가 봅니다. 이전 설명이 두레이에 남는지 확인하지 못했고, 설명을 비우는 일은 두레이 화면에서 합니다.

**여러 건을 한 번에**: "이 다섯 개를 완료로"처럼 내가 여러 건을 부탁하면, Claude가 건마다 대상과 바뀌는 내용을 번호를 붙여 전부 보여 주고 한 번에 허락을 받을 수 있습니다(10건까지). 내가 "전부 해 주세요"라고 하면 보여 준 목록 그대로만, 앞 건의 결과를 본 뒤 한 건씩 차례로 쓰고, 중간에 하나라도 안 되면 거기서 멈추고 알리도록 되어 있습니다. 이것은 Claude가 지키는 규칙이라 완전하지 않습니다 — 목록을 끝까지 읽고 말해 주세요. 동시에 온 쓰기는 프로그램이 거절합니다. 채팅에서는 허락 창이 건마다 뜰 수 있습니다 — 창마다 그 건이 맞는지 봅니다. Code 탭의 자동으로 실행하는 모드에서는 쓰기 도구의 허락 창이 뜨지 않았습니다(실측) — 그곳에서는 한 번의 "전부 해 주세요"가 곧 최대 10건의 쓰기입니다.

쓰기의 조건과 한계 전부는 `SECURITY.md` 3절에 있습니다.

## 5. 업데이트와 지우기

**업데이트** — 자동 업데이트는 없습니다. Releases 페이지에서 새 `.mcpb`를 받아 더블클릭하고 **"업데이트"** 를 누릅니다. 토큰과 웹 주소는 그대로 남습니다. 새 대화에서 "두레이 whoami 불러 줘"로 확인합니다. "업데이트" 버튼이 없으면 이미 같은 버전입니다.

**지우기**
1. Claude Desktop **설정 > 확장 프로그램**에서 dooray-bridge를 제거합니다. 확장 파일과 설정(암호화된 토큰 포함)이 함께 지워집니다.
2. **토큰을 폐기합니다.** 두레이 **개인설정 > API**에서 그 토큰을 지웁니다. 가장 확실한 정리입니다.
3. `~/.dooray-bridge/` 폴더를 지웁니다(설정, 기억해 둔 프로젝트 목록, 감사 로그).

확장을 지울 때 내려받은 Python과 부품도 함께 지워지는지는 확인하지 못했습니다.

## 6. 문제 해결

큰따옴표 안의 글은 프로그램이 내는 문장의 첫머리입니다.

<!-- 코드와 맞춤: error-heads -->
| 증상(나오는 문장의 첫머리) | 원인 | 할 일 |
|---|---|---|
| "두레이 토큰이 유효하지 않습니다" | 토큰이 틀렸거나 폐기됨(상태 401) | 토큰을 새로 발급해 확장 설정의 토큰 칸에 다시 넣습니다 |
| "두레이 토큰을 찾지 못했습니다" | 토큰 칸이 비어 있음 | 확장 설정의 토큰 칸에 넣습니다 |
| "이 항목에 접근할 권한이 없습니다" | 그 프로젝트의 멤버가 아니거나, 사무실 밖에서 접속해 IP 접근 제어에 걸림(상태 403) | 멤버인지 확인합니다. 사무실 밖이면 사무실에서 다시 해 봅니다 |
| "허용되지 않은 두레이 웹 주소입니다" | 웹 주소 칸에 `https://`가 없거나 뒤에 다른 것이 붙음 | 웹 주소 칸을 `https://회사이름.dooray.com` 까지만 적습니다 |
| "두레이 요청 제한에 걸렸습니다" | 짧은 시간에 요청이 많았음(상태 429) | 잠시 뒤 다시 부탁합니다 |
| "두레이에 연결하지 못했습니다" | 인터넷 연결 | 연결을 확인합니다 |
| "API 호출 상한 50회를 넘었습니다" | 한 번에 너무 넓게 찾음 | 프로젝트나 기간을 좁혀 다시 부탁합니다 |
<!-- /코드와 맞춤 -->

| 증상 | 원인 | 할 일 |
|---|---|---|
